# Draft: an operation-ID common commit boundary for PP cache state

**Not implemented.** This is the prerequisite for production qualification, not another performance arm. Counts alone cannot repair divergent operation identities, and a whole-PP collective inside `get_new_batch_prefill` can deadlock the pipeline.

1. **Agree on identities before I/O.** PP0 emits a deterministic manifest ordered by `(epoch, sequence, operation-kind, logical-cache-key, token-range, generation)`. Do not assume existing rank-local numeric node/operation IDs identify the same object across stages. Broadcast the manifest using the established forward control cadence. Local dedup/exists fast paths must retain the same manifest entry as an explicit completed no-op, rather than silently omitting its ACK.
2. **Separate completion from visibility.** Each stage performs its layer-local I/O asynchronously and records completion against the agreed ID. Local completion may release private temporary buffers, but may not independently publish backed-up/storage-hit state, alter prefix visibility, select a different logical eviction victim, or reclaim a shared logical operation. Hold required host/tree references until commit; map each agreed key to its local node/generation.
3. **Advance only a shared contiguous watermark.** A stage reports the largest contiguous manifest prefix it has completed, never a count of unrelated ACKs. Carry last-round readiness back on an independently paired asynchronous control path integrated with the scheduler's existing reverse cadence; PP0 publishes the minimum readiness frontier in the next normal forward control round. Every rank applies the same committed prefix in order. The reverse path must be reviewed against the PP schedule before coding; no blocking all-reduce or wait-for-a-later-forward inside the prefill path.
4. **Bound resources and fail explicitly.** Pin only a bounded number of uncommitted operations/bytes. At the bound, defer new backup admission while allowing scheduler/communication progress. A permanent missing ID, differing manifest digest, or stale generation triggers a bounded diagnostic failure with per-stage manifests and ACKs, not an unbounded drain or silent count clipping. Reset/restart increments the epoch; reject stale ACKs, make duplicate ACKs idempotent, and define recovery before release.
5. **Implementation entry points.** Split `_drain_backup` completion collection from tree/storage visibility effects; replace count-only accounting around `_pp_drain_counts`/`check_hicache_events`; coordinate candidate selection in `_write_behind_host_tail` and dedup/exists enqueue paths; preserve explicit tags/sequence checking in `_pp_sync`. The existing local debt gauge remains diagnostic until the common frontier owns state changes. CPU/GPU memory and readiness latency must be measured; no unverified performance estimate.
6. **Required gates.** CPU cases: late/missing/duplicate ACK, distinct keys with equal counts, local dedup no-op, divergent host pressure/eviction order, reset epoch, bounded pending memory, and deterministic prefix/eviction decisions. Real PP2 then PP4 writeback/eviction tests must demonstrate identical committed key prefixes and progress under delayed ACKs; inject a missing call to check pairing. Only after correctness and real-MTP accuracy pass should a full performance run be authorized. The current task authorizes no further GPU work.

Open decision: whether to use an existing reverse message or a dedicated nonblocking control channel. Either needs an explicit happens-before diagram and bounded lifetime; adding a conditionally sent second message to the current forward tag repeats an already observed failure.
