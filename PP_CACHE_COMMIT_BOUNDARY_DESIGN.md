# Common commit boundary: implemented phase one and remaining work

Phase one is implemented behind the default-off `SGLANG_HICACHE_PP_COMMON_COMMIT` flag. The earlier draft in this file is superseded for backup/release ACK and storage-belief add/delete effects; the remaining scope below is not implemented or performance-qualified.

The implemented protocol uses canonical epoch/sequence/kind/logical-key identities, independently received physical ACKs, previous-round asynchronous readiness and a contiguous PP0-published commit prefix. Pending effects retain their local resources until common commit. Downstream belief changes travel as leader-assigned proposals, with bounded in-flight credits and lossless bounded payload queues. No whole-PP collective is inserted into the prefill scheduler. Memory/frame limits, reset ownership and the120s age guard remain enforced.

For phase two, inventory prefetch-result tree insertion, L2 write/load completion effects, LRU touch and rehydrate attachment. Give each producer a logical parent/key/range/generation independent of physical page addresses; separate physical completion from visibility. Define which actions are genuinely local and prove their reads cannot change common batch or eviction decisions. Extend the same epoch and ordered commit semantics only after this classification. Do not add conditionally paired messages to the existing forward synchronization channel.

Required next gates: tests for late/missing/duplicate callbacks, different keys with equal counts, rank-local eviction pressure, reset races and backpressure; producer-specific coverage on actual hybrid L3 hits; then scoped PP2/PP4 validation and real-MTP correctness as separately authorized. Current CPU-only SWA coverage and sampled belief mismatch gauges do not prove these phase-two invariants. Any performance comparison must retain exact recipe, protocol and hardware differences. This review does not authorize another GPU run.
