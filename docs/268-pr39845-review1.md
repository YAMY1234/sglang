### Comment 4155701482: prefetched-page beliefs

- The production change records `PoolName.KV` and exactly `hash_value[: completed_tokens // self.page_size]` after the host insert and its actions (`python/sglang/srt/mem_cache/unified_radix_cache.py:2296`). This matches buffer mode's `staged_pages = num_tokens // cache.page_size`, leading hash slice and KV pool (`python/sglang/srt/mem_cache/buffer_mode/pipeline.py:1009`).
- Decision: also record when `host_insert_dropped` is true. The successful read proves L3 presence independently of whether L2 retains it; the one-line code comment states that reason (`python/sglang/srt/mem_cache/unified_radix_cache.py:2296`). Buffer mode likewise keeps the belief if a staged prefetch is later discarded (`python/sglang/srt/mem_cache/buffer_mode/pipeline.py:1012`).
- TP agreement was verified before committing. Completion synchronization groups cover ATTN CP/TP (or TP) and PP (`python/sglang/srt/managers/cache_controller.py:398`). `_reduce_prefetch_ack` MIN-reduces completed tokens across those groups (`python/sglang/srt/managers/cache_controller.py:1334`); the hybrid override calls it and MIN-reduces sidecar hits in stable pool order (`python/sglang/srt/mem_cache/hybrid_cache/hybrid_cache_controller.py:946`). The sync thread enqueues only after reduction (`python/sglang/srt/managers/cache_controller.py:1329`).
- These are the cache's TP replicas: with DP attention, `tp_cache_group` is the attention TP group; otherwise it is the model TP group (`python/sglang/srt/mem_cache/kv_cache_builder.py:316`). Independent DP replicas are not assumed to share cache state.
- The scheduler MIN-reduces queue counts before draining (`python/sglang/srt/mem_cache/unified_radix_cache.py:3101`), copies the reduced completion length into the operation (`python/sglang/srt/mem_cache/unified_radix_cache.py:2996`), and then handles the result (`python/sglang/srt/mem_cache/unified_radix_cache.py:3007`). The handler snapshots that length at `python/sglang/srt/mem_cache/unified_radix_cache.py:2237`. `_check_hybrid_prefetch_result` reads the same length and reduced pool hits and returns a boolean; it does not mutate the caller's length or perform a new rank-local truncation (`python/sglang/srt/mem_cache/unified_radix_cache.py:2385`). Thus the new hash slice is rank-identical under the existing synchronized scheduler protocol; this is source verification, not a distributed execution claim.
- Backup failure is different: its completed-token count can diverge, so that existing drain deliberately records the full hash list (`python/sglang/srt/mem_cache/unified_radix_cache.py:3031`). This change preserves that behavior.
