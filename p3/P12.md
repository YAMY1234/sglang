# P12 shallow P KV-first transfer

Keep the j4569012-PCp launch package (fork native 6fb0b992d93, helper
deb51f492f5 + e2f2a76f5f2 and its helper-runtime/final-extra). Replace only the
fork checkout with this branch using `git archive`, in a new immutable directory;
verify source blob IDs before launch. In particular retain Flash-Next staging,
4 slots × 1024 MiB, TP2/DCP1/PP1, the original ports, buffers and instrumentation.

After the frozen PC+ environment on **P**, source `p3/env_p12.sh 0` (old send)
or `p3/env_p12.sh 1` (KV-first send). The recipe changes only
`SGLANG_GDN_PD_SHALLOW_SEND_PIPELINE`. FUSED and CHOLQR_MIXED stay 0;
FULLN, DEFERRED and JOIN_OFFLOAD stay 1. D is unchanged.

## Live received-byte gate (integration-owned)

Use the same new source checkout on P/D. Gate runs are isolated from timings.
On **both P and D** set the following, to separate role directories visible to
the checker (copy artifacts from D if the nodes do not share the directory):

```bash
export SGLANG_FLASHNEXT_PD_STAGING_PROOF_DIR=/out/p12-positive/P  # D: .../D
export SGLANG_FLASHNEXT_PD_STAGING_PROOF_TENSORS=1
```

On **P only**, enable P12 and `SGLANG_GDN_PD_P12_WIRE_REPLAY=1`.
This gate waits for precisely one request's publication, holds the original
source/page ownership, and transports those same P bytes with the old and new
Endpoint schedules before the worker sends its **one** original aux/Success.
Both passes use the real backend and D scatter; there is no second forward.
The proof auditor independently reads local tensor rows (including physical
page padding). Handoff-only latent fields are compared in the D staging buffer,
where the existing protocol retains them. Snapshot files include their actual
device and are written atomically. Both P/D audits must match.

With the existing servers running, execute (substitute the frozen endpoints):

```bash
python p3/p12_wire_client.py --p http://P:PORT --d http://D:PORT \
  --bootstrap-host P --bootstrap-port BOOTSTRAP_PORT --mode positive \
  --out /out/p12-positive/client.json
python p3/p12_wire_check.py --snapshots '/out/p12-positive/**/*.pt' \
  --out /out/p12-positive/equal.json
```

The client sends 1025 and 4097 tokens with two greedy output tokens. The checker
requires all four P/D × before/after snapshots, TP ranks 0/1, short/long and
non-page-aligned prompts, KV, factors (a/U/W/count), h31 and boundary payloads.
It uses `torch.equal` on actual byte tensors, without an N−1 mask or tolerance.
CPU-origin receipts cannot pass the CLI. Client and reader must both pass.
Required P logs include full-N/deferred publication activation,
`PD_SHALLOW_SEND_PIPELINE_ACTIVE staged=True ...` and
`P12_WIRE_REPLAY_ACTIVE ... timing_eligible=False`.

## Live negative gates

Restart the same package twice, in separate output directories, with replay
**unset**. Both roles retain PROOF_DIR/PROOF_TENSORS as above. P12 stays 1.
For each mode `event` / `abort`, set on P only:

```bash
export SGLANG_GDN_PD_P12_WIRE_NEGATIVE=event  # next restart: abort
```

Run the client with the corresponding `--mode event` or `--mode abort`.
Only its explicitly named `p12-negative-MODE-*` request is injected; the next
five ordinary requests must succeed (more than the four staging slots).

* `event`: after actual independent KV DMA returns, substitute an incomplete
  publication-query result on this request's fence. The original `wait_aux`
  must raise FactorPublicationError before late gather, state or aux. This is
  a readiness rejection control; it does not alter source factor data, event
  storage or the CUDA schedule. The module test additionally deliberately
  copies a late field before publication and checks that the byte oracle fails.
* `abort`: at that same between-phases boundary, call the original manager's
  `conclude_failure`; original native failure/abort/drain notifications handle
  D ownership. No new abort protocol is introduced.

D snapshots its actual destination rows before granting SLOT and after native
DMA-drain acknowledgement, while it still owns the room. It records any
unexpected READY. Merge the event and abort proof directories, then:

```bash
python p3/p12_wire_check.py --negative '/out/p12-event/**/*.pt' \
  --negative '/out/p12-abort/**/*.pt' --out /out/p12-negative.json
```

The checker requires both modes on both TP ranks: real KV backend completion,
an event rejection where applicable, no READY, native drain, and unchanged D
destination rows by `torch.equal`. Missing drain, unexpected READY, changed rows
or CPU-origin receipts fail. Both clients must report the expected D abort and
five healthy completions; timeout/disconnection is not an expected abort.
Retain native worker/canary logs and all receipts. These controls deliberately
fail one request each and are never performance inputs.

## Timing gate and handoff

Restart without **all four** proof/replay controls (PROOF_DIR, PROOF_TENSORS,
WIRE_REPLAY, WIRE_NEGATIVE); compare only `env_p12.sh 0` versus `1`.
Preserve `transfer_enqueue`, `transfer_backend`, `send_aux`, `transfer_state`
instrumentation. Use CPU times from the same node; do not subtract GPU timestamps.
WS-3's `pd_xfer_split.py --gate micro RUN` and `--gate ab NEW OLD` consume the
original j4569012 directory layout; `pd_tail.py` v2 builds request tail tables.

Pre-registered micro: enqueue → first backend median ≤10 ms (baseline 22.3 ms),
aux unchanged. An aux tolerance is still awaiting lead adjudication; do not
silently adopt WS-3's proposed max(1 ms,10%). Then pd1n C8/600 s, request paired:
first byte ≥10 ms earlier, system fixed P_send+P_ext+D ≤0 ms, fallback 0.
Only passing gates authorize the S/C+/PC+ C8 window. Tail differences are
reported separately from the fixed-cost mechanism decision. Gate and A/B jobs
are integration-owned; P3 does not submit duplicate jobs.

Local evidence: real native worker/Endpoint/catalog/Triton byte-copy code with
CPU-interpreted CUDA scheduling and modeled memcpy backend. This validates the
protocol tools, positive bytes and failure controls; it is **not** live D/RDMA,
CUDA compilation, a timing result or production admission.
